# 📖 Week Overview

Software engineering involves more than writing code.

Professional software development requires planning, requirements analysis, system design, implementation, testing, documentation and maintenance.

Throughout the programme, the student has learned several programming and development concepts.

Week 11 brings these concepts together by introducing the structured processes used to develop reliable software systems.

The module also prepares the student for the final capstone project in Week 12.

By the end of the week, the student should have a documented project plan, defined requirements, a proposed architecture, test cases and a working prototype.

## 2. What is Software Engineering? — 20 Minutes

Software engineering is the systematic application of engineering principles and practices to software development and maintenance.

### Software Engineering Activities

- Understanding problems
- Gathering requirements
- Designing solutions
- Writing code
- Testing software
- Documenting systems
- Maintaining applications

### Programming vs Software Engineering

| Programming | Software Engineering |
|---|---|
| Focuses on implementing code | Covers the full software lifecycle |
| Solves programming tasks | Addresses user and system needs |
| Emphasises program logic | Includes design, testing and maintenance |
| Often individual activities | Frequently involves collaboration |

## 3. Software Development Life Cycle — 30 Minutes

The SDLC describes stages involved in developing and maintaining software.

### Common Phases

1. Planning
2. Requirements Analysis
3. Design
4. Implementation
5. Testing
6. Deployment
7. Maintenance

### Example: School Management System

**Planning:** Identify the problem.

**Requirements:** Determine what the school needs.

**Design:** Define system components and database tables.

**Implementation:** Write Python code.

**Testing:** Verify that features work correctly.

**Deployment:** Make the application available to users.

**Maintenance:** Fix defects and improve features.

### Introduction to Development Approaches

## 4. Requirements Engineering — 25 Minutes

Requirements describe what a system should do and the constraints under which it operates.

### Functional Requirements

Describe system behaviour.

Examples:

- Register students.
- Search student records.
- Record examination scores.
- Calculate averages.
- Display reports.

### Non-Functional Requirements

Describe quality characteristics or constraints.

Examples:

- Easy to use
- Reliable
- Maintainable
- Secure handling of data
- Acceptable response time

### User Stories

A user story describes a feature from the user's perspective.

Example:

> As a school administrator, I want to register students so that their information can be stored and retrieved.

### Acceptance Criteria

Acceptance criteria describe conditions that must be satisfied.

Example:

- A student can be registered.
- Every student has a unique ID.
- Invalid ages are rejected.
- Successful registration displays confirmation.

## 4. Introduction to Software Testing — 25 Minutes

Software testing helps verify that an application behaves as expected.

### Common Testing Types

**Unit Testing**

Tests individual functions or components.

**Integration Testing**

Tests whether components work together.

**System Testing**

Tests the application as a complete system.

### Example Unit Test

```python
import unittest

def calculate_average(scores):
    if not scores:
        return None

    return sum(scores) / len(scores)


class TestAverage(unittest.TestCase):

    def test_average(self):
        self.assertEqual(
            calculate_average([70, 80, 90]),
            80
        )

    def test_empty_scores(self):
        self.assertIsNone(
            calculate_average([])
        )


if __name__ == "__main__":
    unittest.main()
```

### Running the Test

```bash
python3 -m unittest
```

### Discussion

What is the difference between testing and debugging?
